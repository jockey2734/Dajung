# ADR-026: 사용자 동의 기반 웹 검색·일반 답변 폴백

**상태:** 채택 (2026-07-16)

## 배경

다정의 기본 RAG 답변은 검색된 동아리 문서만 근거로 삼는 폐쇄형 정책을 유지한다. 그러나 재검색까지 수행한 뒤에도 최고 rerank 점수가 임계값보다 낮으면, 기존 동작은 근거가 부족한 상태로 생성 노드에 진입해 "자료 없음" 답변으로 끝났다. 사용자는 같은 질문을 외부 공개 정보나 일반 지식으로 다시 물을 방법이 필요하지만, 내부 문서 답변과 외부 답변을 혼동해서는 안 된다.

`docs/webapp-spec.md` S26은 이 예외를 사용자 명시 동의와 별도 출처 표기를 조건으로 허용한다. 명세에는 ADR-014로 적혀 있으나 기존 `ADR-LOG.md`에서 ADR-014는 이미 PWA 온라인 전용 정책에 배정되어 있고 ADR-025까지 사용 중이므로, 역사적 결정을 덮어쓰지 않고 다음 번호인 ADR-026을 사용한다.

## 검토한 선택지

1. **폐쇄형 RAG만 유지:** 근거가 없으면 항상 자료 없음으로 종료한다.
2. **검색 실패 즉시 자동 웹 검색:** 별도 확인 없이 외부 검색으로 전환한다.
3. **LangGraph interrupt로 한 턴 안에서 승인 대기:** 그래프 상태를 중단·재개한다.
4. **두 턴 동의 방식:** 첫 턴은 웹 검색 제안으로 정상 종료하고, 사용자가 선택한 새 턴만 `web` 또는 `plain` 모드로 실행한다.
5. **별도 검색 벤더 도입:** Brave 등 외부 검색 API와 키를 추가한다.

## 결정

선택지 4를 채택한다.

- 기본 `rag` 모드는 기존 라우터, 검색, permission, rerank, 문서 인용 경로를 그대로 사용한다.
- knowledge/handover 검색에서 재시도 소진 후에도 최고 점수가 임계값 미만이면 고정 문구 `문서 검색에 실패했습니다. 웹 검색을 시도해보시겠습니까?`와 `offer=web_search`를 반환하고 턴을 종료한다.
- 사용자의 후속 선택은 새 요청의 `mode=web|plain`으로 표현한다. 두 모드는 graph entry에서 라우터, retrieve, permission을 모두 우회한다.
- `web`은 기존 Anthropic 키와 Sonnet 설정을 사용해 서버측 web search tool을 호출한다. 도구 형식은 `web_search_20250305`, 호출 상한은 config `web_search_max_uses=3`이다. 근거는 `kind=web`, `title`, `url`로 반환한다.
- `plain`은 도구와 검색 자료 없이 일반 지식만 생성하며 동아리 내부 사실을 단정하지 않는다.
- 웹 답변 첫 줄은 `(웹 검색 결과 — 동아리 내부 자료 아님)`, 일반 답변 첫 줄은 `(동아리 자료·웹 근거 없음 — 일반 지식 답변)`으로 고정한다.
- 기존 문서 인용에는 `kind=doc`을 추가한다. RAG의 마커와 출처 필드는 바꾸지 않는다.
- 모든 모드는 같은 일일 질문 한도를 차감한다.

Anthropic 도구 선택은 [Anthropic 공식 Web search tool 문서](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)를 기준으로 한다.

## 사유

두 턴 방식은 외부 검색 전에 사용자의 의사를 명시적으로 확인하면서 현재 SSE·메시지 저장 계약을 유지한다. MemorySaver 기반 interrupt는 프로세스 재시작에 취약하고 MVP2 예산 승인 흐름과 책임이 섞인다. Anthropic 서버측 도구는 이미 허용된 provider, API key, `api.anthropic.com` 이그레스를 재사용하므로 새 비밀정보와 운영 의존성이 없다.

## 보안·정직성 경계

- `web`과 `plain`은 Qdrant를 조회하지 않으며 candidate, reranked, restricted 청크를 프롬프트에 넣지 않는다.
- user memory와 같은 세션 history는 맥락으로만 주입하고 문서 또는 웹 근거로 취급하지 않는다.
- 웹 결과 내부의 명령과 역할 변경 지시는 무시한다.
- 외부 웹 출처는 동아리 내부 자료로 표현하지 않는다.
- `plain`은 다정의 사람, 규칙, 일정, 재정 등 내부 사실을 모르면 운영진 확인을 안내한다.
- 이름과 동아리 역할 외 개인정보를 문서, 테스트, 로그에 새로 넣지 않는다.

## 트레이드오프와 결과

- 사용자는 제안 후 버튼을 눌러 새 턴을 시작해야 하므로 한 번의 추가 상호작용이 필요하다.
- 웹 검색은 Anthropic 사용 비용과 지연을 늘리지만 `max_uses=3`으로 상한을 둔다.
- 웹 결과의 정확성과 최신성은 내부 문서와 같은 수준으로 보장할 수 없으므로 디스클레이머와 citation kind를 항상 노출한다.
- 프론트엔드는 후속 S27에서 `done.offer` 버튼과 `kind=web` 링크 렌더링을 구현한다. S26은 백엔드 계약까지만 제공한다.

## 기각한 대안

- 선택지 1은 안전하지만 사용자가 같은 질문을 다시 활용할 경로가 없다.
- 선택지 2는 명시 동의 원칙을 위반하고 내부·외부 근거를 혼동시킨다.
- 선택지 3은 영속 체크포인터가 없는 현재 구조에서 복구 신뢰성이 부족하다.
- 선택지 5는 새 provider, key, 이그레스, 비용 관리가 필요해 S26 범위를 불필요하게 넓힌다.
