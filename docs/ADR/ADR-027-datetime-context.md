# ADR-027: 현재 날짜·학기 컨텍스트 주입

**상태:** 채택 (2026-07-26)

## 배경

MVP1 완성 시점까지 시스템의 어떤 프롬프트에도 현재 날짜가 없다. 확인한 지점은 다음과 같다.

- `api/app/llm/anthropic_client.py`의 system 블록은 톤, 답변 규칙, 첨부 규칙, 사용자 메모리 네 개뿐이다.
- `api/app/graph/nodes/router.py`의 `ROUTER_PROMPT`에도 날짜가 없어 "이번 학기" 같은 표현이 `semester_hint`로 해석되지 않고 항상 `null`이 된다.
- `api/app/rag/answer.py`의 `build_context()`는 청크 payload에 이미 존재하는 `semester`와 `last_modified`를 컨텍스트에 싣지 않는다. 모델 입장에서 2024년 자료와 2026년 자료가 동등하다.

그 결과 "지금 몇 학기야", "이번 학기 총무가 뭐 해야 해", "다음 활동 언제야" 같은 운영 질문에서 모델이 학습 시점을 기준으로 답하거나 근거 없이 추측한다. 지식문서 감사에서 확인한 학기별 문서 충돌도 모델이 최신 여부를 판단할 근거가 없어 그대로 노출된다.

동아리 업무는 학기 단위로 반복되므로 "오늘"과 "현재 학기"는 답변 품질의 전제 조건이다.

## 검토한 선택지

1. **주입하지 않는다:** 사용자가 질문에 날짜를 직접 적게 한다.
2. **`prompts/persona/tone.md`에 날짜를 적어둔다:** 파일 텍스트로 관리한다.
3. **각 생성 노드의 `user_text` 앞에 날짜 줄을 붙인다:** 노드마다 개별 구현한다.
4. **`_system_blocks()` 마지막에 날짜 블록을 붙인다:** 모든 생성 경로가 한 지점을 공유한다.
5. **날짜와 함께 학사일정 테이블(개강일·종강일·시험기간)을 주입한다:** 정확한 학사 국면을 제공한다.

## 결정

선택지 4를 채택하고, 라우터 프롬프트와 검색 컨텍스트에도 같은 시각 기준을 확장 적용한다.

- `api/app/core/clock.py`를 신설해 KST 시각, 현재 학기, 학사 국면, 프롬프트 문자열 생성을 한곳에서 담당한다. 기존 `api/app/roster.py`의 `KST`와 `current_semester()`를 이 모듈로 옮기고 `roster.py`는 재export한다. 그래프 노드가 `roster.py`를 import하면 SQLAlchemy와 `db.models`까지 딸려오므로 core 계층 분리가 필요하다.
- 학기 경계는 기존 규칙을 그대로 유지한다. 1학기 시작 3/1, 2학기 시작 9/1, 1~2월은 전년도 2학기다. 프론트엔드 `web/src/lib/semester.ts`와 동일해야 한다.
- 학사 국면은 월 기준 고정으로 산출한다. 3~6월 1학기 학기중, 7~8월 여름방학, 9~12월 2학기 학기중, 1~2월 겨울방학이다.
- 날짜 블록은 `_system_blocks()`가 반환하는 배열의 **맨 마지막**에 붙이며 **`cache_control`을 붙이지 않는다.**
- 라우터 프롬프트에는 오늘 날짜와 함께 **현재 학기 문자열을 계산된 형태로 직접 주입한다.** 로컬 `gemma4:e4b`에게 날짜에서 학기를 계산하게 시키지 않는다.
- `build_context()`는 각 자료 항목에 `학기`와 `수정` 값을 함께 싣고, `ANSWER_RULES`에 학기 충돌 시 최신 우선 및 기준 학기 명시 조항을 추가한다.
- 시간대는 `Asia/Seoul` 하드코딩을 유지한다. 설정값으로 분리하지 않는다.

## 사유

`answer_system_blocks()`와 `fallback_system_blocks()`가 `_system_blocks()`를 공유하므로, 한 곳에 붙이면 `generate`, `generate_handover`, `web_generate`, `plain_generate`와 `rag/answer.py`의 직렬 디버그 경로까지 동시에 적용된다. 노드별 주입은 같은 문안을 다섯 번 복제하고 새 생성 노드가 추가될 때마다 누락될 위험을 만든다.

`tone.md` 방식은 매일 사람이 파일을 고쳐야 하므로 유지되지 않는다.

## 캐시 브레이크포인트 제약

Anthropic prompt caching은 `cache_control` 블록을 최대 4개까지 허용한다. 현재 톤, 답변 규칙, 첨부 규칙, 사용자 메모리로 이미 정확히 4개를 사용 중이므로 날짜 블록에 `cache_control`을 붙이면 상한을 넘겨 API가 요청을 거부한다.

또한 캐시는 prefix 기준이므로, 매일 값이 바뀌는 블록을 앞쪽에 끼워 넣으면 그 뒤의 모든 블록 캐시가 날마다 무효화된다. 맨 뒤에 무캐시로 붙이면 앞쪽 prefix 캐시가 그대로 적중하고, 날짜 블록 자체는 캐시할 실익이 없다.

이 제약은 회귀하기 쉬우므로 `api/tests/graph/test_generate_prompts.py`에서 `cache_control` 보유 블록 수 상한과 날짜 블록의 위치·무캐시를 단언한다.

## 정직성 경계

날짜는 시스템이 제공하는 사실이며 검색 자료의 추측이 아니므로, 인용 마커 없이 답해도 정직성 정책 위반이 아니다.

다만 **오늘 날짜를 아는 것과 일정을 아는 것은 다르다.** 모델이 현재 시각을 근거 삼아 존재하지 않는 향후 일정을 구성하지 않도록, 주입 규칙에 "현재 시각으로 추론할 수 없는 미래 일정은 단정하지 않고 운영진 확인을 안내한다"를 명시한다. `~/Eval_checklist.md`의 H(정직성) 채점이 이 경계의 회귀 감시 지점이다.

`clarify.py`는 LLM 호출이 없는 결정적 노드이고 출력이 사용자에게 그대로 보이므로 주입 대상에서 제외한다. S24에서 같은 성격의 오기를 한 차례 정정한 바 있다.

## 트레이드오프와 결과

- 매 요청 system 블록이 한 줄 수준으로 길어진다. 토큰 증가는 무시할 수준이다.
- 날짜 블록은 캐시되지 않으므로 해당 블록만큼은 매번 입력 토큰으로 과금된다. 캐시 적중률 자체는 앞쪽 prefix에서 유지된다.
- 학사 국면이 월 기준 고정이라 실제 개강·종강일과 며칠 어긋난다. 학사일정 테이블을 새로 관리할 값어치가 없다고 판단해 감수한다(선택지 5 기각).
- `build_context()` 포맷 변경으로 자료당 수십 자가 늘지만, 학기 충돌 판단 근거를 얻는 편익이 크다.
- 라우터가 `semester_hint`를 실제로 채우기 시작하면 검색 필터 동작이 달라지므로, 학기 힌트가 잘못 잡혀 최신 자료가 걸러지는지 검증이 필요하다.

## 기각한 대안

- 선택지 1은 사용자에게 시스템의 한계를 떠넘긴다.
- 선택지 2는 수동 갱신 의존이라 반드시 낡는다.
- 선택지 3은 동일 문안을 다섯 곳에 복제하고 신규 노드에서 누락된다.
- 선택지 5는 학사일정 데이터 관리 부담이 편익보다 크다. 필요해지면 MVP2 이후 별도 결정으로 다룬다.
