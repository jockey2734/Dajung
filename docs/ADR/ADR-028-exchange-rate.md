# ADR-028: 조건부 환율 조회 — 수출입은행 매매기준율 + 결정적 사전 노드

**상태:** 채택 (2026-07-26)

## 배경

지식문서에 외화 가격이 그대로 들어 있고, 오늘 환율 없이는 답할 수 없는 질문이 이미 존재한다.

- `data/knowledge/tea/중국차_구매_가이드.md` §4의 실구매 기록표는 **CNY 상품가**로 적혀 있다(서호용정 A급 104.39 CNY·AAA급 201.69 CNY, 대홍포 156.92 CNY). 문서 자신이 "환율, 결제수단, 지불수속비와 포장 무게가 달라지므로 위안화 상품가만 원화로 환산하지 말고 실제 원화 결제 총액을 예산 기준으로 삼는다"고 경고한다.
- `data/knowledge/tea/서양차_구매_가이드.md` §2는 **개인 자가사용 면세 한도 미화 150달러**(미국발 200달러)와 "1센트라도 초과하면 초과분이 아니라 전체 금액에 약 40% 관세+부가세"를 명시한다. 유로·파운드로 공동구매를 진행하는 상황에서 오늘 환율 없이는 한도 판단 자체가 불가능하다.

현재 `api/app` 전체에 통화 처리 코드는 없다. `db/models.py`의 `cost_usd`는 LLM 호출 비용 기록용이며 환율과 무관하다. 따라서 모델은 과거 환율로 계산하거나 추측한다. 면세 한도 판단을 틀리면 주문 전액에 40% 과세가 붙어 실제 금전 손실이 발생한다.

## 검토한 선택지

1. **주입하지 않는다:** 사용자가 환율을 직접 계산해 질문에 적는다.
2. **기존 Anthropic 웹 검색 재사용:** ADR-026의 `web_search_20250305`로 환율을 찾는다.
3. **Anthropic tool-use 루프:** `get_exchange_rate` 도구를 정의하고 모델이 필요할 때 호출한다.
4. **키 불필요 공개 API(frankfurter.app 등):** ECB 고시 환율을 무료로 받는다.
5. **한국수출입은행 오픈API + 결정적 사전 노드:** 질문·자료에 외화 신호가 있을 때만 매매기준율을 1회 조회해 컨텍스트에 주입한다.
6. **관세청 주간 과세환율:** 통관 판정의 법적 기준 환율을 직접 쓴다.

## 결정

선택지 5를 채택한다.

- 데이터 소스는 **한국수출입은행 오픈API 매매기준율**(`deal_bas_r`)이다. API 키는 `.env`의 `DAJUNG_KOREAEXIM_API_KEY`로만 주입한다.
- **엔드포인트는 `https://oapi.koreaexim.go.kr/site/program/financial/exchangeJSON`이다.** 구 도메인 `www.koreaexim.go.kr`은 2025-06-25 이전 방식이며 **2026-04-30 종료됐다** — 이미 지난 날짜이므로 구 도메인을 쓰면 동작하지 않는다.
- 조회 시점은 **결정적 사전 노드**가 판정한다. LangGraph에서 `rerank` 다음, `generate`/`generate_handover` 이전에 노드 하나(`fx_context`)를 두고, 질문 또는 검색된 청크에 외화·직구·면세 신호가 있을 때만 조회한다. 신호가 없으면 외부 호출을 하지 않는다.
- 조회 결과는 노드가 완성한 텍스트 블록으로 State에 담아 생성 프롬프트에 주입한다. **인용 출처가 아니므로 `[번호]` 마커를 붙이지 않는다.**
- 면세 한도 안내는 **미국발 200달러, 그 외 모든 국가 150달러**로 고정하며, **타오바오 등 중국 직구에도 150달러 한도를 적용한다**(운하 확정, 2026-07-26).
- 조회 실패 시 환율을 추정하지 않는다. **어떤 오류인지 구분해 밝히고** 사용자가 직접 확인하도록 안내한다. 면세 한도와 40% 과세 규칙 자체는 환율과 무관하므로 실패 시에도 안내한다.

## 사유

**선택지 3(tool-use)을 쓰지 않은 이유가 결정의 핵심이다.** 현재 생성 노드는 `anthropic_client.complete()` 단일샷 호출이다. 도구 루프를 넣으면 `stop_reason=tool_use` 처리와 다중 왕복이 생기고, SSE 스트림 계약·인용 마커 계약·일일 질문 한도 회계가 모두 복잡해진다. 환율 필요 여부는 정규식으로 충분히 판정되는 결정적 문제이므로, 모델에게 판단을 위임할 이유가 없다. 이는 S28에서 날짜를 system 블록에 결정적으로 주입한 것과 같은 판단이다.

**선택지 2(웹 검색)를 쓰지 않은 이유:** `mode=web`은 graph entry에서 retrieval을 우회하므로 **문서의 CNY 가격과 오늘 환율을 한 답변에서 결합할 수 없다.** 게다가 2턴 명시 동의가 필수라(ADR-026) "대홍포 얼마야"에 곧바로 답할 수 없고, 검색 결과의 숫자 정밀도도 보장되지 않는다.

**선택지 4(키리스 ECB)를 쓰지 않은 이유:** 무료·무키라는 운영 이점은 크지만 유럽중앙은행 고시라 한국 매매기준율과 다르다. 동아리 예산 문서가 원화 기준이므로 한국 고시환율이 맞다.

`httpx>=0.27`은 이미 `pyproject.toml`에 있으므로 신규 파이썬 의존성은 없다.

## 관세청 과세환율과의 관계 — 정직성 경계

**통관 과세 판정의 법적 기준 환율은 관세청 주간 과세환율이며, 본 결정이 쓰는 수출입은행 매매기준율과 다르다.** 선택지 6을 기각한 것은 주단위 고시 조회·적용 로직을 추가할 값어치가 현 단계에 없다고 봤기 때문이며, 매매기준율이 통관 기준이라고 판단한 것이 아니다.

따라서 주입 문안에 **"통관 과세환율은 관세청 주간 과세환율이며 위 매매기준율과 다르다. 한도 근처 금액은 안전하다고 단정하지 말고 여유를 두거나 관세청 고시를 직접 확인하도록 안내한다"**를 반드시 포함한다. 150달러 경계에서 "안전합니다"라고 단정하는 답변은 정직성 정책 위반으로 취급한다.

## 보안 경계

- API 키는 `.env`에만 둔다(SECURITY.md §6). `.env.example`에는 키 이름만 적고 값은 비운다.
- **`authkey`가 로그·예외 메시지·사용자 노출 오류 문구·URL 로깅에 실려서는 안 된다.** 요청 URL을 그대로 로깅하지 않고 `searchdate`와 `result` 코드만 로깅한다.
- **TLS 검증을 끄지 않는다.** `verify=False`는 금지이며, 인증서 문제가 생기면 오류로 처리해 보고한다.
- 새 아웃바운드 목적지 `oapi.koreaexim.go.kr` 1건이 추가된다. ufw는 `allow outgoing`(SECURITY.md §5.4)이라 방화벽 변경은 필요 없다. 전송하는 데이터는 API 키와 조회 날짜뿐이며 **동아리 데이터·질문 내용은 전송하지 않는다**.
- 일일 요청 한도는 **키당 1,000회**이고 초과 시 `result=4`로 데이터가 오지 않는다. TTL 캐시로 실사용량을 하루 수 회 수준으로 묶는다.
- **키 수명 주의**: 최초 신청 시 입력한 개인정보 보유기간(2년) 만료 시 키가 폐기되며, 사전에 재동의 안내 메일이 발송된다. 재동의를 놓치면 `result=3`(인증코드 오류)로 조용히 실패하므로, 오류 종류를 구분해 노출하는 설계가 이 상황의 진단 경로가 된다.

## 트레이드오프와 결과

- 외부 의존성 1건과 시크릿 1건이 늘어난다. 이것이 이 결정의 실질 비용이다.
- 주말·공휴일과 영업일 이른 시각에는 당일 고시가 없어 직전 영업일로 역행 조회해야 한다. 따라서 표시되는 환율은 최신 영업일 기준이며 문안에 고시 기준일을 항상 밝힌다.
- 엔화(JPY)와 인도네시아 루피아(IDR)·베트남 동(VND)·캄보디아 리엘(KHR)은 **100단위 호가**다. `cur_unit`의 `(100)` 접미를 파싱해 나눠야 하며, 통화를 늘릴 때 같은 함정이 재발한다.
- 위안화는 `cur_unit`이 `CNH`(역외위안)로 온다. 사용자와 문서는 "위안/CNY"라 부르므로 매핑이 필요하다.
- 환율 블록은 프롬프트 토큰을 수십 개 늘리지만 발동 조건이 좁아 대부분의 턴에는 영향이 없다.
- `web`/`plain` 모드는 retrieval을 우회하므로 이 경로를 타지 않는다. 환율만 묻는 순수 질문은 검색 실패 → `offer_web` → 웹 검색으로 흐른다. 의도된 동작이며 필요 시 후속 명세로 확장한다.

## 기각한 대안

- 선택지 1은 세금 폭탄 리스크를 사용자에게 그대로 남긴다.
- 선택지 2는 문서 가격과 환율을 한 답변에 결합할 수 없고 2턴 동의가 강제된다.
- 선택지 3은 단일샷 생성 계약을 파괴하는 대가가 결정적 정규식 판정으로 얻는 것보다 크다.
- 선택지 4는 한국 원화 예산 문서와 기준이 어긋난다.
- 선택지 6은 통관 판정에는 정확하나 주단위 고시 조회·적용 로직 부담이 현 단계 편익을 넘는다. 대신 매매기준율과 다르다는 사실을 문안에 명시해 오판을 막는다.
